# Архитектура проекта

## Основные части

```text
HTTP client
    |
    v
Controller -> Service -> PostgreSQL
                    |
                    v
                  Redis
```

`Controller` принимает HTTP-запросы и возвращает JSON-ответы.

`Service` содержит основную логику: проверяет URL, создаёт короткий код, проверяет срок жизни ссылки и увеличивает счётчик переходов.

`PostgreSQL` хранит ссылки постоянно. Redis используется как быстрый кэш для часто запрашиваемых ссылок.

## Создание ссылки

1. Клиент отправляет URL в `POST /api/v1/shorten`.
2. Service проверяет URL и генерирует код из 7 символов.
3. Ссылка сохраняется в PostgreSQL.
4. Ответ кладётся в Redis.
5. Клиент получает ответ со статусом `201 Created`.

## Переход по ссылке

1. Клиент открывает `GET /{shortCode}`.
2. Приложение сначала проверяет Redis.
3. Если записи нет в кэше, приложение читает её из PostgreSQL.
4. Счётчик переходов увеличивается в базе.
5. Приложение возвращает `302 Found` и заголовок `Location`.

## Почему Redis не является основной базой

Redis может очистить данные или перезапуститься. Поэтому PostgreSQL остаётся источником истины, а Redis можно восстановить из базы.
